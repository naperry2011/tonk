## Build & Development Commands

```bash
npm install        # Install dependencies
npm run dev        # Start Vite dev server (http://localhost:5173)
npm run build      # Bundle to dist/
npm run preview    # Preview production build
npm test           # Run Vitest suites (tests/)
npm run lint       # Run ESLint
```

Mobile app (Flutter, in `app/`):

```bash
cd app
flutter pub get    # Install dependencies
flutter analyze    # Static analysis
flutter test       # Engine + widget tests (app/test/)
flutter run        # Run on a connected Android device/emulator
```

CI (GitHub Actions) runs two jobs on every push and PR to main: web (lint, test, build) and flutter (analyze, test).

## Mobile App (`app/`)

Flutter app for Android and iOS (ADR-004). Android is tested on the Windows PC; iOS builds and testing happen on a Mac. The web version stays in place and keeps shipping.

- `app/lib/engine/` - Pure Dart port of `src/game/` (no Flutter imports). Keep rules in sync with the JS engine; event names, phase strings, and win-condition strings match.
- `app/lib/engine/ai_turn.dart` - `runAiTurn(game)` plays an AI turn one action per iteration (port of `GameUI.handleAITurn`). The UI awaits between steps; tests call `.toList()`.
- Events: `game.addListener((GameEvent e) {...})` with sealed event classes in `game_event.dart`.
- Randomness: pass `Game(random: Random(seed))` for deterministic deals and AI; `deckFactory` lets tests stack the deck.
- Save/resume: `Game.toJson()` / `Game.fromJson()` (includes match scores and round number).
- `app/lib/state/game_controller.dart` - `GameController` (ChangeNotifier): human actions, paced AI turns (`aiStepDelay`), round settlement into `RoundSummary`, autosave after every step. Rejected actions set `error` instead of throwing.
- `app/lib/data/save_store.dart` - `SaveStore` (shared_preferences, key `tonk_game_state`); `MemorySaveStore` for tests.
- `app/lib/ui/` - `screens/` (home, table, settings), `widgets/` (playing card + `DealIn` animation, opponent seat with speech bubble, hand, round-end panel, celebration confetti), `theme.dart` (TonkColors), `themes.dart` (6 `DeckTheme`s ported from styles/themes.css, 3 `TableTheme`s), `table_feel.dart` (sfx + haptics from `GameController.events`).
- Characters: `app/assets/content/characters.json` is the AI roster and table talk (names, colors, emoji, `AiStyle` knobs, lines per `TalkKey`). Loaded into `Roster` (`lib/content/roster.dart`); `TableTalk` (`lib/state/table_talk.dart`) picks lines per event with a cooldown. Talk is clean by design; `test/content/roster_test.dart` fails on cursing or unknown keys.
- AI play style: `AiStyle` (`lib/engine/ai_style.dart`) on each `ComputerPlayer` (knock thresholds, raise appetite, fold chance, low-discard grabbing). Defaults match the web AI.
- Betting (mobile only; the web version has no folding): the human may raise once per turn; each AI may raise once per round at the start of its turn. Everyone still in must call or fold. Folding (`Game.fold`) sits a player out for the round: skipped in turns, ignored by knock/stock-empty comparisons, can't win the pot, still takes hand points at round end. Last player in wins with `WinCondition.allFolded`. The human answers AI raises via `GameController.pendingRaise` / `answerRaise(call:)`; a pending prompt survives restarts.
- Settings: `SettingsController` (`lib/data/settings_store.dart`, key `tonk_settings`): deck theme, table theme, sound, haptics, nickname.
- Sound effects: `app/assets/sfx/*.wav`, generated by `node tool/gen_sfx.mjs` (run from `app/`). Audio uses `mixWithOthers` focus so it never pauses the player's music.
- Android check without the preview tools: adb is at `%LOCALAPPDATA%/Android/Sdk/platform-tools/adb.exe` (not on PATH); use `exec-out screencap -p` for screenshots and `shell input tap x y` for taps.
- App wiring: `lib/app_services.dart` (`AppServices`) bundles the roster, the match and daily `GameController`s, settings, profile, and feel; screens take `services`. `connectProfile` routes each settled round (`onRoundSettled` with `RoundFacts`) and each match end (`onMatchEnded`, chips cash-out) into the profile.
- Progression (`lib/meta/`): `progression.dart` is pure rules (XP per round, level curve `50*n*(n-1)`, `unlockTrack`, 10 achievements). `ProfileController` (key `tonk_profile`) owns XP, bankroll, stats, achievements, daily bonus and streaks; inject `clock` in tests. `match_setup.dart`: `startMatch` (takes the 1,000 buy-in, seats unlocked characters), `dailyOpponents`, `unlockedCharacters`.
- Chips: bankroll starts at 2,500; each match costs a 1,000 buy-in and cashes out at match end; +300 daily bonus; a broke player can refill to 1,000. Play money only, never sold.
- Daily challenge: one round via `GameController.newDaily(day, opponents)` (`MatchMode.daily`), seeded by the date so the deal is the same for everyone; own save slot `tonk_daily_state`.
- Unlocks: start with Card Room, Rose Gold/Midnight backs, Uncle Ray/Mr. Earl/Keisha/Lil Tre; the rest unlock by level. `AppServices.enforceUnlocks` resets locked theme choices.
- Layout: test at 360dp wide (the widget tests do); the emulator is wider and hides overflows. See `docs/ai/roadmap.md` for milestones.
- Release and store: `store/README.md` is the release checklist (upload key, `key.properties`, `flutter build appbundle --release`, Play Console answers, iOS notes, listing copy). App ID `com.tonk.tonk` is permanent once uploaded. Release builds sign with `android/key.properties` (gitignored) and fall back to the debug key without it. Age rating: simulated gambling (betting play chips every round) means 18+ on iOS; keep chips play-only, never sold.
- Icon, splash, and store art are generated from code: `app/tool/icon/` (icon painter, `flutter test tool/icon/render_icon_test.dart` then `dart run flutter_launcher_icons`), `dart run flutter_native_splash:create`, and `app/tool/store/render_store_assets_test.dart` (512 icon, feature graphic, screenshot conversion to RGB because Play rejects alpha). Play screenshots must be 9:16 (1080x1920): capture with `adb shell wm size 1080x1920`, then `wm size reset`.
- Portrait lock lives in the Android manifest and iOS Info.plist, not in Dart (awaiting `SystemChrome.setPreferredOrientations` at startup stalled the first frame about 3s). Don't await slow work before `runApp`.
- Performance: measure on a real phone. The emulator's software GPU makes cold start look like 5-7s; the Samsung S948U measures about 0.2s.

## Architecture Overview

The web version of Tonk is a browser-based card game built with vanilla JavaScript (ES6 modules), HTML5, CSS3, and Vite. No external runtime dependencies.

### Core Structure

- `src/main.js` - Entry point; creates Game and GameUI instances
- `src/game/` - Pure game logic (no DOM)
- `src/ui/` - DOM rendering and user interaction
- `src/utils/` - Storage and helper utilities
- `styles/` - CSS files (main.css, cards.css, layout.css, themes.css)

### Key Patterns

**Event-Driven Architecture**: Game.js is a custom event emitter. GameUI subscribes via `game.on(event, callback)` and updates the DOM reactively. Key events: `gameInitialized`, `turnStart`, `turnEnd`, `cardDrawn`, `cardDiscarded`, `spreadLaid`, `spreadHit`, `knock`, `gameOver`.

**Game Phases** (defined in `rules.js`): `PRE_GAME` → `INITIAL_TONK_CHECK` → `START_OF_TURN` → `DRAW` → `ACTION` → `GAME_OVER`. Actions must check `game.phase` before executing.

**Turn Flow**: At `START_OF_TURN`, player can knock or lay spreads. Call `game.proceedToDraw()` to enter `DRAW` phase. After drawing, phase becomes `ACTION` where player can lay spreads, hit spreads, then must discard.

**Spread Validation**: `Spread.validate(cards)` returns `{ valid: bool, type: 'book'|'run'|null }`. Books = 3-4 same rank. Runs = 3+ sequential same suit.

**AI**: ComputerPlayer extends Player. Key methods: `decideDraw()`, `findBestSpread()`, `shouldKnock()`, `decideDiscard()`, `decideBet()`.

**Betting System**: Ante-based betting with chips. Constants in `rules.js`: `BETTING.STARTING_CHIPS`, `BETTING.ANTE_AMOUNT`, `BETTING.RAISE_OPTIONS`.

### Debugging

In dev mode (`npm run dev`), `window.game` and `window.ui` are available for console inspection.

### localStorage Keys

- `tonk_settings` - User preferences, including the selected deck theme (`deckTheme`)
- `tonk_statistics` - Win/loss stats, recorded on each round's gameOver
- `tonk_game_state` - Reserved in storage.js for save/load; not currently used

## Game Rules Quick Reference

- **Spreads**: Books (3-4 same rank) or Runs (3+ sequential same suit)
- **Card Points**: A=1, 2-10=face value, J/Q/K=10
- **Initial Tonk**: 49-50 points at deal = automatic win (if multiple players have it, redeal)
- **Knock/Drop**: At start of turn, claim lowest points. If wrong, opponent with lowest wins ("caught")
- **Win Conditions**: TONK (empty hand), INITIAL_TONK, KNOCK, CAUGHT, STOCK_EMPTY
- **Match**: First to 100 points loses
- **Fold (mobile app)**: Passing on a raise means folding: out for the round, can't win the pot, hand points still count. If everyone else folds, the last player in wins (ALL_FOLDED)
